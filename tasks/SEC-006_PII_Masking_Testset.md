## 🎯 Summary
- 기능명: [SEC-006] PII 마스킹 회귀 테스트셋 200건 설계 및 작성
- 목적: Privacy-Guard 엔진(SEC-001, 002)의 신뢰성을 지속적으로 검증하기 위해, 총 200건의 기밀 데이터를 포함한 테스트 케이스(주민번호, 계좌번호, 커스텀 키워드 등)를 구성하고 CI 파이프라인에 통합한다.

## 🔗 References (Spec & Context)
- SRS 문서: §4.1.4 (REQ-FUNC-019), §4.2.3 (REQ-NF-012)

## 📝 Task Breakdown
- [ ] 더미 PII 데이터 100건 생성 (형식이 맞는 가상의 주민등록번호/외국인등록번호 포함 문장).
- [ ] 더미 계좌/금융 데이터 50건 생성 (가상의 계좌번호, 카드번호 포함 문장).
- [ ] 커스텀 규칙 및 NER 타겟 더미 데이터 50건 생성 (특정 프로젝트명, 가상 임원 이름 포함 문장).
- [ ] 위 200건의 테스트셋을 자동화 테스트 프레임워크(Jest 등)의 Input-Output Fixture 로 작성 (예상 Output은 정확히 `***` 로 치환된 문자열).
- [ ] `npm run test:masking` 과 같은 명령어로 200건 전체의 마스킹 누락률(False Negative)을 측정하고 F1-Score를 반환하는 테스트 스위트 작성.

## ✅ Acceptance Criteria (BDD)
- **Given**: SEC-001 및 SEC-002 마스킹 파이프라인 모듈이 구현된 상태에서
- **When**: 개발자가 200건의 PII 테스트셋을 대상으로 자동화 테스트를 실행하면
- **Then**: 200건 모든 문장에서 타겟 기밀 정보가 단 1건의 누락도 없이(100% 탐지율) `***` 로 치환되어야 하며, 테스트가 `PASS` 되어야 한다.
- **Then**: 단 하나의 PII라도 노출 상태로 유지되면 테스트는 `FAIL` 처리되어야 한다.

## 🛡️ Constraints (NFRs)
- 설계 제약: 해당 테스트셋 데이터는 실제 인물의 개인정보가 우연히 포함되지 않도록 난수 생성기(Faker 등)를 사용하여 완전한 허구의 데이터로만 작성되어야 한다.
- 아키텍처 제약: 이 테스트 스위트는 INF-003(CI 파이프라인)의 Build Break(배포 차단) 기준점이 되므로 실행 속도가 빠르고 결정적(Deterministic)이어야 한다.

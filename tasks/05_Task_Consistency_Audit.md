### 근본 원인 분석

v4에서 APP 태스크를 재정의하면서 **번호를 재배정**했지만, 개별 파일은 v2~v3 시점에 이미 생성된 상태로 **갱신되지 않음**.

파일 내용 기준으로 v2~v3 → v4 매핑을 추정하면:

| 개별 파일 (v2~v3 실제 내용) | v4 마스터에서 대응되는 역할 |
|---|---|
| APP-001 (Next.js 초기화) | v4에서 제거됨 (INF 또는 기본 전제) |
| APP-002 (디자인 시스템) | v4에서 제거됨 (DES 또는 기본 전제) |

| APP-004 (에디터/Trust-Anchor) | → v4 **APP-001** (HITL 편집 에디터) + **APP-002** (딥링크 호버) |

## 6. 권장 조치

> [!IMPORTANT]
> **SSOT 원칙 위반**입니다. 마스터 리스트(v4)와 개별 파일 중 하나를 **단일 진실 소스(SSOT)**로 확정해야 합니다.

### 옵션 A: 마스터 리스트(v4) 기준으로 개별 파일 재생성
- v4의 APP/QA/TEST 정의에 맞춰 16개 파일을 **삭제 후 재작성**
- v2~v3에서만 존재했던 기능(Next.js 초기화, 디자인 시스템, OWASP 스캔, DB 롤백 등)은 별도 논의 후 신규 ID 부여 또는 폐기

### 옵션 B: 개별 파일(v2~v3) 기준으로 마스터 리스트 복원
- 개별 파일의 상세 BDD/Breakdown이 이미 고품질이므로 이를 존중
- 마스터 리스트의 APP/QA/TEST 섹션을 개별 파일 기준으로 **역방향 갱신**
- v4에서 신규 추가된 기능(Push Notify UI, 환각률 Alert 등)은 새 파일로 추가

### 옵션 C: 혼합 — 개별 파일 내용 보존 + ID 재배정
- 기존 고품질 파일의 **내용은 유지**하되, v4 마스터의 **ID 체계에 맞게 파일명과 frontmatter만 갱신**
- v4에서 새로 정의된 기능은 신규 파일로 추가 작성

## :white_check_mark: Task Breakdown (실행 계획)
- [ ] **ChromaDB `PersistentClient`** 초기화 (`%LocalAppData%\CorpBrain\vectors\`). FAISS 미사용
- [ ] **명시적 임베딩 함수 주입** — Ollama `POST /api/embeddings` (`nomic-embed-text`, 768차원) 래퍼 구현. **Chroma 기본 임베딩 함수(ONNX 자동 다운로드)를 사용하지 않는다** (REQ-NF-005 위반 방지). HTTP 호출은 `NetworkGuard.request(purpose='llm_local', ...)`를 경유하며 이 모듈에서 `httpx`·`requests`를 직접 import하지 않는다 (`DEC-15`)
- [ ] **워크스페이스당 컬렉션** 생성 — 이름 `ws_<workspace_id_hex>`, `metadata={"hnsw:space": "cosine"}`
- [ ] 기존 컬렉션 존재 시 로드(Load), 없을 시 신규 생성 분기 처리 로직 작성
- [ ] **임베딩 모델 버전 가드** — `App_Config`의 `embedding_model`/`embedding_dim`과 대조하여 불일치 시 사용자 동의 후 컬렉션 재생성 + 전체 재임베딩 (조용한 혼용 금지)
- [ ] chunk 메타데이터 스키마 적용: `{workspace_id, file_id, chunk_index, folder_1depth}`
- [ ] **`VectorDBManager` API 설계 (`DEC-09`)**: `upsert_file_chunks(file_id, chunks)` — 내부에서 chunk ID를 **`f"{file_id}:{chunk_index}"`** 로 계산 / `delete_file(file_id)` — `where={"file_id": …}` 필터 삭제 / `drop_workspace(workspace_id)` — `delete_collection` 1회. **chunk ID 목록을 반환하거나 SQLite에 저장하는 인터페이스를 만들지 않는다**
- [ ] 파일 재분석은 **`delete_file()` → `upsert_file_chunks()` 순서**로 강제한다 (upsert 단독 호출 시 축소된 문서의 잉여 chunk가 잔존)
- [ ] 검색 후처리에서 `File_Meta`에 없는 `file_id`의 chunk를 결과에서 제외하고 **지연 삭제(lazy delete)** 한다 (고아 벡터 회수 — 별도 GC 스케줄러 미구현)
- [ ] 기초 CRUD(문서 추가/조회/`file_id` 필터 삭제) 테스트 스크립트 작성

## :test_tube: Acceptance Criteria (BDD/GWT)
Scenario 1: 벡터 DB 컬렉션 생성
- Given: 지정된 벡터 DB 저장 경로가 비어있음
- When: 클라이언트 초기화 함수를 호출함
- Then: `%LocalAppData%\CorpBrain\vectors\`에 벡터 DB 파일이 생성되고 `ws_<id>` 컬렉션이 코사인 공간으로 활성화된다.

Scenario 2: 임베딩 차원 검증
- Given: `nomic-embed-text` 모델이 준비된 Ollama 데몬이 주어짐
- When: 임의의 텍스트 청크 1개를 임베딩함
- Then: 반환된 벡터의 길이가 **768**이며 컬렉션에 정상 upsert된다.

Scenario 4: 재분석 시 잉여 chunk 미잔존 (DEC-09)
- Given: chunk 5개로 임베딩된 파일이 있고, 문서가 축소되어 재분석 시 chunk가 3개가 됨
- When: `delete_file()` → `upsert_file_chunks()` 순서로 재분석함
- Then: 해당 `file_id`의 chunk가 **정확히 3개**만 남고, 이전 4·5번 chunk가 검색 결과에 나타나지 않는다.

Scenario 5: 워크스페이스 삭제 시 벡터 정리 (DEC-09)
- Given: 벡터가 적재된 워크스페이스가 존재함
- When: 워크스페이스 삭제를 요청함
- Then: 벡터 컬렉션이 먼저 drop되고 이어서 SQLite 행이 CASCADE 삭제되어, 고아 벡터가 남지 않는다.

Scenario 3: 임베딩 모델 불일치 감지
- Given: `App_Config.embedding_model`이 기존 값과 다른 모델로 변경된 상태
- When: 벡터 DB 클라이언트를 초기화함
- Then: 불일치를 감지하여 사용자 동의 요청 상태로 전이하고, 동의 없이 기존 컬렉션에 신규 차원 벡터를 섞어 넣지 않는다.

## :gear: Technical & Non-Functional Constraints
- 보안/격리: 로컬 파일 시스템 내부에만 영속 저장되며 외부 클라우드 의존성이 없어야 함.
- **네트워크: 임베딩 호출은 `127.0.0.1`의 Ollama 데몬으로만 향하며, `NetworkGuard`(`purpose='llm_local'`) 관문을 통과한다** (`DEC-15`). Chroma가 임베딩 모델을 자동 다운로드하려는 경로(기본 ONNX 임베딩 함수)를 절대 활성화하지 않는다 (REQ-NF-005).
- **트랜잭션 경계 (`DEC-09`)**: Chroma 호출을 SQLite 쓰기 트랜잭션 내부에서 실행하지 않는다. 순서는 `Chroma delete → Chroma upsert → SQLite parse_status 커밋`으로 고정한다 (중간 크래시 시 재처리로 수렴하는 멱등 상태만 남는다).

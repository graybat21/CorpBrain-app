## 🎯 Summary
- 기능명: [DES-003] HITL 승인 대시보드 UI/UX 설계
- 목적: 자동 생성된 문서 초안을 실무자가 직관적으로 검토, 수정, 승인, 반려할 수 있는 최적화된 에디터 및 대시보드 환경을 설계한다.

## 🔗 References (Spec & Context)
- SRS 문서: §4.1.5 F5 (REQ-FUNC-020 ~ 023)

## 📝 Task Breakdown
- [ ] 처리 대기 중인 초안 목록(Pending Drafts)을 시각화하는 메인 대시보드 리스트 뷰 설계.
- [ ] 개별 초안의 상세 내용을 렌더링하고 직접 수정할 수 있는 WYSIWYG 에디터 또는 텍스트 에리어 UI 설계.
- [ ] 하단(또는 우측) 플로팅 바를 통한 '승인(위키 발행)', '수정', '반려' 핵심 액션 버튼 컴포넌트 설계.
- [ ] 반려 선택 시 반려 사유를 입력받는 팝업 또는 폼 UI 디자인.
- [ ] 위키 발행 완료(승인 완료) 시 제공될 시각적 피드백(축하 애니메이션 또는 Success 모달) 설계.

## ✅ Acceptance Criteria (BDD)
- **Given**: 프론트엔드 개발자가 HITL 에디터 UI(APP-001)를 개발하려는 상태에서
- **When**: DES-003의 디자인 가이드라인을 열람하면
- **Then**: 목록 조회에서부터 개별 초안 검토, 내용 교정(수정), 최종 승인 및 반려 플로우까지 전체 사용자 여정(User Journey)에 필요한 모든 화면 상태(빈 화면, 로딩, 에러 포함)가 정의되어 있어야 한다.

## 🛡️ Constraints (NFRs)
- 설계 제약: 문서 교정 작업의 특성상 피로도를 낮출 수 있는 가독성 높은 타이포그래피와 레이아웃 구조(여백, 명도 대비 등)를 필수로 적용해야 한다.
- 프론트엔드 연계: APP-001, APP-009 구현 태스크의 명확한 시각적 기준점(Baseline)으로 작용해야 한다.

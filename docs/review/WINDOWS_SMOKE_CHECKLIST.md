# Windows 수동 스모크 체크리스트 (프론트엔드 왕복 검증)

> **목적**: 이슈 #91 의 미충족 AC — "최소 1개 페이지 왕복 테스트" — 를 자동 러너 없이 충족한다.
> **대상**: `CorpBrain.exe` (PyInstaller `--onefile`, pywebview + WebView2)
> **관련 이슈**: #94 (이 문서로 범위 재정의), #14 (exe 조립·실행 검증)

---

## 1. 이 문서가 존재하는 이유

`tests/test_ws_fe_01.py` 외 프론트엔드 관련 pytest 는 **정적 검증**이다. 소스 문자열과 OpenAPI 스키마를 비교해 계약 드리프트를 잡지만, **렌더된 페이지가 실제로 백엔드와 왕복하는지는 증명하지 못한다.**

| pytest 정적 검증이 잡는 것 | 잡지 못하는 것 |
|---|---|
| 페이지가 읽는 필드가 응답에 존재 (DTO 이름 변경 시 실패) | `useEffect` 누락 → 호출이 아예 발생하지 않음 |
| 승인 목록 밖 의존성 추가, 외부 전송 코드 | 조건 분기로 호출 미도달 |
| Empty State·라벨·분기가 소스에 존재 | 응답 필드를 잘못 읽어 빈 값이 렌더됨 |
| API 경로 상수가 실제 라우트와 일치 | WebView2 에서의 실제 렌더·레이아웃·애니메이션 |

Vitest + Testing Library + jsdom 도입은 **#91 시점의 확정 결정("pytest 계약 테스트만")과 충돌**하므로 채택하지 않는다. 대신 왕복을 **사람이 한 번 확인하는 절차**로 정의한다. jsdom 은 어차피 WebView2 가 아니므로, 셸 환경에서의 실제 동작은 이 방식만이 증명한다.

**한계를 명시한다**: 이 체크리스트는 회귀 방지 자동화가 아니다. 릴리스 전 1회 수행하는 게이트이며, 매 커밋마다 돌아가지 않는다. 계약 드리프트의 상시 방어는 pytest 정적 검증이 담당한다.

## 2. 사전 준비

```powershell
# 1) SPA 번들 빌드
npm ci
npm run build

# 2) exe 패키징
python -m PyInstaller CorpBrain.spec

# 3) 실행
dist\CorpBrain.exe
```

WebView2 Runtime 이 없으면 Evergreen Bootstrapper 안내 다이얼로그가 뜨고 **크래시 없이 종료**되어야 한다 (DEC-01). 이것도 검증 항목이다 → §3.0.

준비물:
- 문서 20건 이상이 들어 있는 폴더 2개 (다중 루트 병합 검증용)
- 1-depth 하위 폴더가 2개 이상인 구조 (위키 탭 격리 검증용)
- `.docx` / `.pdf` / `.txt` / `.md` 각 1건 이상

## 3. 체크리스트

각 항목은 **"화면에서 무엇을 하면"** → **"무엇이 보여야 하는가"** 형태다. 하나라도 실패하면 그 항목의 이슈 번호를 참조해 회귀로 등록한다.

### 3.0 셸 기동 (DEC-01 / #14)

- [ ] `CorpBrain.exe` 단일 파일 실행으로 창이 뜬다 (별도 설치·Node 프로세스 없음)
- [ ] 작업 관리자에 `node.exe` 가 **없다**
- [ ] 창 크기 조절·최대화 시 레이아웃이 깨지지 않는다
- [ ] 로그가 `%LocalAppData%\CorpBrain\logs\` 에 생성된다
- [ ] (가능하면) WebView2 Runtime 미설치 PC 에서 안내 다이얼로그 후 정상 종료

### 3.1 워크스페이스 생성 — `CreateWorkspaceModal` → `POST /workspace`

- [ ] 폴더 2개를 선택해 워크스페이스를 만들면 사이드바에 즉시 나타난다
- [ ] 같은 폴더를 두 번 선택하면 1개로 합쳐진다 (#66)
- [ ] 존재하지 않는 경로를 넣으면 Toast 로 거부되고 워크스페이스가 생기지 않는다
- [ ] 앱을 완전히 종료하고 재실행해도 워크스페이스와 폴더 목록이 그대로다 (#66)

### 3.2 스캔 및 진행률 — `FilesPage` → `POST /scan` + 1초 폴링 (#6, DEC-04)

- [ ] 스캔 실행 시 프로그레스 바가 `N/M` 과 퍼센트로 갱신된다
- [ ] 완료 시 **Toast** 가 뜬다 (전체 화면 모달이 아니다 — #6 에서 AC 정정)
- [ ] 완료 후 폴링이 멈춘다 (개발자 도구 Network 에 1초 요청이 계속 쌓이지 않음)
- [ ] 블랙리스트 폴더(`.git`, `node_modules`)의 파일이 목록에 없다 (#47)
- [ ] **10,000개 초과 폴더**: 절단 경고 Toast 가 뜨고, 마지막 Toast 가 "완료" 라고만 말하지 않는다 (#64)

### 3.3 대시보드 통계 바인딩 — `DashboardPage` → `GET /scan/summary` + `GET /analytics/summary` (#64)

- [ ] '총 스캔 문서' 수치가 실제 스캔 결과와 일치한다 (0 이나 빈 값이 아니다)
- [ ] 정상 스캔 후 캡션이 초록색 "10K Limit Guard 정상 (N MB)" 이다
- [ ] **10,000개 초과 스캔 후** 캡션이 주황색 "10,000개 제한 도달 — 일부 파일 미탐색" 으로 바뀐다 (#64 의 핵심 — 하드코딩 라벨 회귀 검출)
- [ ] 폴더를 좁혀 재스캔하면 캡션이 다시 초록색으로 돌아온다 (#64 정렬 결함 회귀 검출)
- [ ] '핵심 중요 문서 (50점+)' 수치가 중요도 분석 후 0 이 아니다 (#1, #4)

### 3.4 고속 분석 정렬 — `FilesPage` (#4)

- [ ] 분석 후 목록이 **중요도 내림차순**이다 (파일명 순이 아니다 — #4 의 원래 결함)
- [ ] 중요도 배지 색상이 점수대별로 구분된다
- [ ] 점수가 모두 0~100 범위다 (#1)

### 3.5 위키 탭 및 딥링크 — `WikiPage` → `GET /wiki` + `POST /deeplink/open` (#17, DEC-08)

- [ ] 1-depth 폴더마다 탭이 하나씩 생기고, 탭 내용이 서로 섞이지 않는다 (#10)
- [ ] 딥링크 배지를 클릭하면 **연결된 실제 파일**이 OS 기본 앱으로 열린다
- [ ] **문서 21건 이상인 폴더**: '참조 파일' 목록에 21번째 이후도 나온다 (#17 의 원래 결함)
- [ ] 목록이 잘렸을 때 "관련 문서 N건이 더 있으나 생략되었습니다" 문구가 보인다 (#17)
- [ ] 위키 마크다운에 **절대 경로가 노출되지 않는다** (`C:\Users\...` 검색 0건 — DEC-08)
- [ ] 파일을 OS 에서 직접 삭제한 뒤 배지가 'Broken' 상태로 표시된다 (#22)

### 3.6 이름 변경 및 Undo — `RenamePage` → `POST /rename/*` (#37, #39, #40, DEC-17)

- [ ] Diff 목록에 old/new 이름이 뜨고, **행별로 개별 승인**할 수 있다 (#40)
- [ ] 적용 후 실제 파일명이 바뀌고 목록이 갱신된다
- [ ] Undo 로 **전부** 원래 이름으로 복원된다 (#39, #43)
- [ ] 같은 Undo 를 두 번 누르면 `ALREADY_UNDONE` 으로 거부된다 (#39)
- [ ] Diff 나 프롬프트에 **절대 경로가 없다** (DEC-17)
- [ ] Undo 후 위키 딥링크가 여전히 정상 동작한다 (DEC-08 late binding — 재분석 없이)

### 3.7 Watcher — `WatcherControl` → `PATCH /watcher` (#56~#60)

- [ ] 모드 전환(즉시/유휴)이 UI 에 반영된다

### 3.8 LLM 설정 — `SettingsPage` → `GET/POST /config/llm` (#30, #31)

- [ ] 엔진 상태 4개 항목(종합/데몬/임베딩/생성)이 각각 표시된다 (DEC-13)

- [ ] 단가를 과거 기준일로 저장하면 그 날짜가 그대로 유지된다 (오늘로 덮이지 않음 — #30 의 핵심 규칙)
- [ ] "추정치 / 실제 청구액과 다를 수 있습니다" 문구가 보인다 (DEC-16)
- [ ] **가격 자동 확인 버튼이 없다** (DEC-15 — 있으면 위반)
- [ ] API Key 저장 후 '등록됨' 으로 바뀌고, **키 값이 어디에도 다시 표시되지 않는다** (DEC-12)

## 4. 실패 기록 양식

실패 항목은 아래 형식으로 이슈에 남긴다. 스크린샷보다 **어떤 응답을 받았는지**가 중요하다.

```
- 항목: §3.3 10,000개 초과 스캔 후 캡션
- 기대: 주황색 "10,000개 제한 도달"
- 실제: 초록색 "10K Limit Guard 정상"
- 응답: GET /scan/summary → {"limit_reached": false}
- 추정: 마지막 scan 태스크의 error_code 가 기록되지 않음
```
